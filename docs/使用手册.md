## 1. DiceManager 是什么

DiceManager 是一个**自托管的 QQ 骰子（TRPG 骰娘）程序管理器**。它通过浏览器里的 Web 面板，
帮你把「装程序 → 登录 QQ → 让骰子和登录端连上 → 守护进程」这一整套动作托管起来。

它管两类程序，这是理解全部操作的前提：

| 角色 | 是什么 | 举例 |
|---|---|---|
| **骰子端**（dice） | 真正干活的程序，接收群消息、跑团、掷骰 | 海豹 SealDice、溯洄 Dice!、青果 OlivaDice、Dice!Next |
| **登录端**（login） | 负责登录 QQ，并把消息转成 OneBot 协议喂给骰子端 | NapCatQQ、Lagrange.OneBot、Lagrange.Milky、LLBot、SnowLuma、Yogurt |

两者的关系是：**登录端登录了 QQ，骰子端才能收到消息**。绝大多数情况下你需要成对部署——
一个登录端 + 一个骰子端。DiceManager 负责把它们连好，并保证 token 两端一致。

DiceManager **不做**这些事：它不实现 QQ 协议、不代你做滑块验证、不改骰子程序的业务逻辑。
遇到 QQ 官方的风控或验证，需要你本人在浏览器里完成。

支持管理的程序清单（共 11 份，5 骰子端 + 6 登录端）：

| 角色 | 程序 | 登录方式 |
|---|---|---|
| 骰子端 | [海豹 SealDice](https://sealdice.com/download) | 外置登录端 / QQ 官方机器人 |
| 骰子端 | [溯洄 Dice!](https://github.com/Dice-Developer-Team/Dice) | 外置登录端（离线上传包） |
| 骰子端 | [青果 OlivaDice](https://github.com/OlivOS-Team/OlivaDiceCore) | 内置（整合包，无需登录端） |
| 骰子端 | [Dice!Next](https://github.com/DiceZone/Dice-Next) | 外置登录端 |
| 骰子端 | [NoneBot2](https://github.com/nonebot/nonebot2) | 外置登录端（需本机 Python ≥3.10） |
| 登录端 | [NapCatQQ](https://github.com/NapNeko/NapCatQQ) | 二维码（WebUI） |
| 登录端 | [Lagrange.OneBot](https://github.com/LagrangeDev/Lagrange.Core) | 二维码 |
| 登录端 | [Lagrange.Milky](https://github.com/LagrangeDev/Lagrange.Core) | 二维码（Milky 协议） |
| 登录端 | [LLBot](https://github.com/LLOneBot/LuckyLilliaBot) | 二维码（v8.0.9+ 需申请 AUTH TOKEN） |
| 登录端 | [SnowLuma](https://github.com/SnowLuma/SnowLuma) | WebUI |
| 登录端 | [Yogurt](https://github.com/LLOneBot/yogurt-pmhq) | 二维码 |

> 青果 OlivaDice 是**整合包**，自带登录客户端，不需要登录端，拓扑图上显示为单节点。

## 2. 两个版本怎么选

| 维度 | 🐧 Linux 服务器版 | 🪟 Windows 单机本地版 |
|---|---|---|
| 定位 | 服务器共享版，多账号承载 | 单机本地工具，单用户 |
| 典型场景 | 云服务器 / VPS 上挂多个 QQ 骰子 | 自己的电脑上挂一两个骰子 |
| 运行账户 | root 或专用账户 | 当前用户（双击即用） |
| 数据目录 | `/var/lib/dicemanager` | `<项目根>/data` |
| 日志目录 | `/var/log/dicemanager` | `<项目根>/data/logs` |
| 程序安装目录 | `/opt/<程序名>` | `<项目根>/package/<程序名>` |
| 常驻方式 | systemd 服务 | 托盘程序 / 启动文件夹快捷方式 |
| 防火墙 | 自动放行 ufw / firewalld 端口 | 不需要（只监听 127.0.0.1） |
| 对外访问 | Nginx + TLS 反代 | 浏览器直接访问本机 |
| 首次密码 | 随机生成，打印在 systemd 日志里 | 网页里设置，输两次 |

**怎么选**：要在服务器上长期挂机、对外提供服务、需要开机自启和进程守护 → Linux 版。
只想在自己电脑上试试、拖个 exe 就跑 → Windows 版。两者功能基本对齐，界面和操作完全一致。

> Windows 版是独立的代码副本，与 Linux 版**不共用代码**，各自演进。因此界面一致但细节可能略有差异，
> 本手册会标注哪些是版本特有的。

## 3. 安装与启动

### 3.1 🐧 Linux 服务器版

**一键部署（推荐）**：

```bash
sudo bash deploy/install.sh                # 完整部署（含前端构建）
sudo bash deploy/install.sh --swap         # 2G 内存的小机器建议加：建 2G swap
sudo bash deploy/install.sh --skip-build   # 已有 web/dist 时跳过 npm 构建
```

脚本会：装系统依赖 → 检查 Python ≥3.10 → 拉代码到 `/opt/dicemanager` → 建 venv 装依赖
→ 构建前端 → 建 `/var/lib`、`/var/log` 目录 → 装并启用 systemd 服务 → 配置 Nginx →
输出访问地址和查看密码的命令。

**手动部署**：

```bash
cd /opt/dicemanager
pip install -r requirements.txt
cd web && npm i && npm run build && cd ..
python -m api.app                    # 监听 127.0.0.1:8765
```

**生产环境配置**：管理面板自身只监听 `127.0.0.1:8765`，需要 Nginx 对外并提供 TLS。
`deploy/nginx-dicemanager.conf` 已含 WebSocket 所需的 `Upgrade`/`Connection` 头配置，直接用即可。
Nginx 的 `client_max_body_size` 需 ≥ 2048m（对齐「离线包上限 2GB」），模板已配置。

**开机自启**：`install.sh` 已装好 systemd 服务，无需额外操作。

```bash
systemctl status dicemanager        # 查看状态
systemctl restart dicemanager       # 重启面板
journalctl -u dicemanager -f        # 跟踪面板日志
```

### 3.2 🪟 Windows 单机本地版

**方式一：开发模式运行**

```bat
pip install -r requirements.txt
cd web && npm install && npm run build && cd ..
deploy\start_dev.bat
::    监听 127.0.0.1:8765
```

**方式二：打包为单文件 exe（推荐给普通用户）**

```bat
deploy\build_exe.bat
::    产物 dist\dicemanager.exe，约 25MB，双击即用
::    data 目录自动生成在 exe 同级
```

打包后的行为：双击 exe 无 CMD 窗口，程序在**系统托盘**运行。
托盘菜单可打开面板、查看状态、退出。`data` 目录紧邻 exe，用户可以直接看到、备份、迁移。

**开机自启**：把 `dicemanager.exe`（或 `start_dev.bat`）的快捷方式放进启动文件夹
（`Win + R` 输入 `shell:startup`）。不需要 nssm，不需要注册成 Windows 服务。

> ⚠️ 关机/重启会杀掉所有骰子程序进程，但注册表里状态仍是 RUNNING。
> 下次打开面板时会自动拉回这些实例，无需手动逐个启动。

### 3.3 打开面板

浏览器访问：

```
http://127.0.0.1:8765
```

🐧 如果通过 Nginx 反代，访问你配置的域名（形如 `https://dicemanager.example.com`）。

## 4. 登录管理面板

面板有密码保护，两版的首次密码获取方式不同。

### 4.1 🐧 Linux 版：随机密码

首次启动时 DiceManager 会生成一个随机管理密码，**打印在 systemd 日志里**：

```bash
journalctl -u dicemanager -n 50 | grep '\[auth\]'
```

用这个密码登录面板即可。密码以 PBKDF2 哈希形式存放在 `/var/lib/dicemanager/auth.json`。

### 4.2 🪟 Windows 版：网页内设置

首次打开面板会**自动进入「设置管理密码」界面**（因为 `data/auth.json` 还不存在），
输入两次新密码即可，之后自动登录。托盘程序不会弹窗打断你。

### 4.3 改密码与忘记密码

- **改密码**：面板内「修改密码」，需要输入旧密码。改成功后所有已登录会话全部失效，
  需用新密码重新登录。
- **忘记密码**（两版通用做法）：删掉凭据文件后重启面板。

  | 版本 | 操作 |
  |---|---|
  | 🐧 | `rm /var/lib/dicemanager/auth.json && systemctl restart dicemanager` |
  | 🪟 | 删除 `<项目根>/data/auth.json`，重新打开 exe |

  🐧 会生成新随机密码（再按 §4.1 查）；🪟 重新进入「设置管理密码」界面。
  **注意**：删除凭据不会影响任何已部署的实例，它们照常运行。

### 4.4 安全提示

- 面板永远只监听 `127.0.0.1`，外部机器无法直接访问。🐧 要对外访问必须自己配 Nginx。
- 登录失败有速率限制，密码用 PBKDF2 哈希存储，token 恒定时间比较。
- 启动命令一律由后端构建，前端无法传入任意命令，从设计上杜绝了命令注入。

## 5. 界面导览

面板顶部是导航，共四个页面：

| 页面 | 作用 |
|---|---|
| **总览** | 拓扑图 + 资源水位 + 程序包/备份管理 + 实例操作（主界面） |
| **新建** | 五步向导，部署一个新实例 |
| **日志中心** | 实时日志、历史回放、跨实例检索 |
| **修改密码** | 改管理密码 |

### 总览页布局

```
┌──────────────────────────────────────────────────┐
│  内存水位条  used/total  ≥90% 变红   [扫描安装目录] │
├──────────────────────────┬───────────────────────┤
│                          │  程序包缓存            │
│      拓扑图               │  ├ sealdice  120MB ✓在用│
│   （节点 + 连线）          │  └ dice!     80MB  可清 │
│                          ├───────────────────────┤
│  ● 海豹      RUNNING      │  备份产物              │
│  │                        │  ├ sealdice-pre-upgrade │
│  └─ ○ NapCat   已连接      │  └ [按天批量清理]      │
│      虚线=已配置未连接     │                        │
│      红线=连接失败        │  定时任务              │
├──────────────────────────┴───────────────────────┤
│  选中节点后：启动/停止/重启/打开WebUI/资源曲线/     │
│              查看日志/备份/升级/删除                │
└──────────────────────────────────────────────────┘
```

**拓扑图连线三态**：

| 线型 | 含义 | 该怎么办 |
|---|---|---|
| 实线绿 | 已连接 | 正常，骰子能收到消息了 |
| 虚线灰 | 已配置但未连接 | 登录端还没登录，或进程没起来 |
| 实线红 | 连接失败 | 看日志排查，多半是 token 不一致或端口不通 |

**节点灰显** = 进程已死但注册表还记着运行中，点「扫描安装目录」可查游离进程/目录。

## 6. 新建实例：五步向导

点导航「新建」进入向导。顶部有进度条显示当前在第几步，**支持断点续跑**——
中途关掉页面或进程崩溃，下次进来会提示「下一步：第 X 步」并直接跳过去。

```
① 选程序  →  ② 部署  →  ③ 登录  →  ④ 互联  →  ⑤ 启动
```

### 第 1 步：选程序

- 选程序名、架构（x64 / arm64）。
- 如果是**骰子端**且该程序支持外置登录端，可以在此选择「登录端」实例关联，
  也可以留到第 4 步再配。留空则只能单端运行，QQ 消息进不来。
- **接入通道**（仅海豹）：清单声明支持多通道时会多出一个下拉。
  - `OneBot 协议`（默认）：走登录端，五步向导，能力完整。
  - `QQ 官方机器人`：免登录端、免互联，向导简化为三步，**规避协议端封号风控**；
    代价是官方接口的主动消息、群管能力受限。选它之后连接要在海豹自己的 WebUI 里
    用 AppID/AppSecret 或扫码完成。
- 显示每个程序的**内存预估**和**前置依赖**。有依赖缺失时向导会直接给下载链接。
  （🪟 例如 NapCat 需要先装 Windows QQ 客户端。）

### 第 2 步：部署

点「开始部署」，DiceManager 会：

1. 优先用**本地程序包**（如果你在第 1 步上传过）；
2. 没有则按清单策略**从上游下载**（支持 `DM_GITHUB_MIRROR` 镜像加速）；
3. 校验完整性（可选 `sha256`）；
4. 解压并归一化顶层目录；
5. 检查必备文件。

**端口自动分配**：按角色（WebUI / ob11 / milky / satori）批量分配，默认端口被占用时
自动 +1 重试。所以**实际端口可能不等于清单里的默认端口，以总览显示的为准**。

**目录冲突弹窗**：如果目标目录已存在，会弹窗让你二选一：

- 「直接使用」——校验必备文件后复用该目录（适合你之前手工部署过）
- 「新建序号文件夹」——自动创建 `<程序名>-2`、`<程序名>-3`…

**部署失败了怎么办**：向导会展开失败面板，两个出口：

- 「重试下载」——重新走一遍下载部署
- 「上传压缩包并部署」——手动选一个离线包上传，自动接着重试

> 🐧 国内直连 GitHub 不稳时，可设环境变量 `DM_GITHUB_MIRROR=https://ghfast.top` 走镜像。
> 上游不提供可运行包的程序（如溯洄 Dice!）只能靠「上传离线包」落地。

**离线包格式**：`zip` / `tar.gz` / `tar.xz` / `tar.bz2` / `tar`，上限 2GB。
DiceManager 按**文件魔数**识别真实格式（不看扩展名），所以改扩展名也没用（好事）。

### 第 3 步：登录

只有**登录端**需要这一步。界面按程序不同分四种形态：

| 形态 | 你要做的事 |
|---|---|
| 二维码 | 面板里会实时显示二维码图片，拿手机 QQ 扫。二维码不刷新了点「刷新二维码」（会重启登录进程） |
| 账号密码 | 填 QQ 号 + 密码 + 协议 |
| WebUI 指引 | 面板给步骤，你在程序自带面板里登录 |
| 无需登录 | 青果整合包等，自动跳过本步 |

**登录完成的判定**：进程存活 **且** 链路连通。满足后面板自动跳到第 4 步。
你也可以点「跳过登录」强行推进（比如想先配好互联再登录）。

> ⚠️ **滑块验证不会被自动处理**。弹出滑块时面板只给你一个验证链接，
> 需要你本人点开链接在浏览器里手动完成。这是 QQ 官方的风控，绕不过去。

> ⚠️ **LLBot v8.0.9+ 强制要求 AUTH TOKEN**，需要到其官方快速登录平台申请后填入向导。
> 没填会在启动时报错。

### 第 4 步：互联配置

配置骰子端和登录端之间的连接。三件事：**方向**、**地址**、**token**。

- 多数情况下**全部留空自动生成**即可，向导会保证两端 token 一致。
- **方向**：正向 WS（骰子端主动连登录端）/ 反向 WS（登录端主动连骰子端）。
  适配器已经按程序特性选好，一般不用改。
- **多对多**：一个登录端可以带多个骰子端，一个骰子端也可以挂多个登录端（多账号）。
  第 4 步会列出所有关联，逐条指定账号绑定。
- ⚠️ 选了该程序的**兼容矩阵为空**却没关联任何登录端时，向导会**明确警告**——
  别造出一个连不通的实例。

**如果适配器返回「需手动配置」**：说明它没能通过程序自身的 API 写进去
（token 失效、端口未回读成功等）。这时面板会给出手动路径指引，
你按提示在程序自己的 WebUI 里手动创建连接，然后把信息回填。

### 第 5 步：启动

点「启动」显式启动（不会自动启）。DiceManager 会：

1. 执行首启一次性准备（`prepare_start`）；
2. 由后端构建启动命令；
3. 拉起进程，状态变 `RUNNING`；
4. 面板给出该实例的 WebUI 直达链接。

**状态机**（理解这个有助于排查）：

```
UNDEPLOYED → DEPLOYING → AWAIT_LOGIN → CONFIGURED → RUNNING
     ↑            ↓            ↓            ↑           ↓
     └────────────┴────────────┴────────────┴───────────┘
                    任一状态 → ERROR（可恢复到部署/登录）
```

## 7. 实例日常操作

在总览页点选一个节点，下方出现操作按钮：

| 操作 | 说明 |
|---|---|
| **启动 / 停止 / 重启** | 停止会把状态落回 CONFIGURED，面板重启时**不会**被自动拉起（这是刻意设计） |
| **管理应用** | 展开该程序的管理面板：自带 WebUI 的程序可一键打开；依赖型程序（NoneBot2）可在此装卸插件（见 §10.1） |
| **资源曲线** | 看 24h 内存/CPU 折线与峰值 |
| **查看日志** | 跳到日志中心并选中该实例 |
| **上传备份** | 导入一个备份包（见 §9） |
| **导出整目录备份 / 导出数据备份** | 生成 tar.gz 备份（见 §9） |
| **诊断连接** | 仅骰子端有。检查两端链路，报告问题在哪一环 |
| **检查更新 / 升级** | 见 §10 |
| **删除** | 两级确认，见下 |

### 7.1 删除实例（两级确认）

1. 第一次确认：删实例记录；
2. 第二次确认：**是否连程序目录一起删**。

删除链路顺序是：停进程 → 释放端口 → 删目录 → 写墓碑。
如果目录删除失败，实例记录会保留，你可以直接重试，不会变成无主孤儿目录。

> 部分程序（如溯洄 Dice!）的 manifest 声明了「删除保留存档」，第二次确认的文案会提示
> 建议保留存档目录。保留存档后，配置能回滚但群里的存档数据还在。

### 7.2 进程守护（自动重启）

DiceManager 把每个实例当自己的子进程守护，规则如下：

| 行为 | 参数 |
|---|---|
| 崩溃自动重启 | 指数退避，从 1s 起，上限 300s，每次崩溃退避 +1 |
| 熔断 | 300s 滑动窗口内崩溃 ≥5 次 → **停止**自动重启并写日志 |
| 窗口清零 | 上次启动后稳定运行超 300s，重启计数窗口清零 |
| 内存环形缓冲 | 2000 行（供日志回放） |
| 日志文件滚动 | 单文件 50MB，超出转存 `.log.1`；保留 7 天 |

**触发熔断了怎么办**：这是保护机制，说明程序一直崩溃。**去看日志找根因**，别直接重试。
修好后手动点「启动」即可（重启计数不复位是正常的）。

### 7.3 面板重启后的自动恢复

面板重启（更新服务、服务器重启、重新打开 exe）会连带杀掉所有实例进程，
但注册表里状态还是 RUNNING——历史表现是「面板显示在跑，实际全离线」。

现在面板启动时会自动拉回**仅状态为 RUNNING** 的实例：

- 触发范围：**只有 RUNNING**。你主动停过的（落回 CONFIGURED）、待扫码的（AWAIT_LOGIN）、
  出错的（ERROR）都不会被强行拉起；
- 逐实例独立处理：一个失败不影响其余，失败原因写进面板日志和该实例自己的日志；
- 关闭开关：环境变量 `DM_AUTO_RESUME=0`（排障时不想被打扰可以关掉）；
- 🐧 手动触发：重启服务即可。日志里会看到 `[resume] 实例 xxx 已自动拉起`。

### 7.4 扫描安装目录

总览页顶部「扫描安装目录」会拿安装根下的目录和相关进程跟注册表比对，分三类展示：

| 类别 | 含义 | 可操作 |
|---|---|---|
| `owned` 受管 | 有对应实例记录 | 正常，不显示按钮 |
| `orphan` 游离目录 | 目录名像程序名但没实例记录（手工部署残留、删除失败残留） | **可删除** |
| `external` 外部程序 | 无关软件（alist、containerd 等） | 仅展示，**不提供删除** |

游离进程也会列出，可一键结束（只会结束 exe/工作目录确实落在安装根下、
且不属于任何实例或管理器自身的进程）。

> ⚠️ 删除游离目录是不可逆操作，点之前确认里面没有你手工放的数据。

## 8. 日志中心

导航「日志中心」。每实例一条 WebSocket 流，2 秒刷新。

**工具栏功能**：

| 功能 | 说明 |
|---|---|
| 实例下拉 | 切换实例，切换即重连并清空当前视图 |
| 关键字过滤 | 服务端过滤（正则转义，大小写不敏感），不是前端隐藏 |
| 暂停/继续跟随 | 暂停后新日志仍进缓冲区，继续时补上（不丢行） |
| 复制 | 复制当前视图全部行 |
| 下载 | 下载完整日志文件（含历史，不只是视图里的 2000 行） |

**历史回放**：切到实例时先回放 ring 缓冲里的最近 2000 行，再接实时流。
**进程重启不丢日志**——日志在磁盘上，不在内存里。

**错误行高亮**：含 `ERROR` / `FATAL` / `Traceback` / `panic` 的行标红显示。

**跨实例全局搜索**：搜索框输入**至少 2 个字符**，回车执行。范围是
每个实例的 ring 缓冲（最近 2000 行）+ 磁盘日志尾部 2MB。
结果列表里点「查看该实例」可跳转到对应实例的日志视图。

> 限制：全局搜索只扫日志尾部 2MB，不是全文检索。找很久以前的日志请直接下载文件。

## 9. 备份、导出与迁移

### 9.1 两种备份口径

| 口径 | 包含 | 用在哪 |
|---|---|---|
| **整目录备份**（full） | 程序 + 配置 + 存档 + 数据，全部打包 | 换机器、重装系统前的完整快照 |
| **数据备份**（data） | 仅应用数据/存档（对应程序自身备份功能的口径） | 日常备份存档，防误删数据 |

导出方式：总览页选中实例 → 「导出整目录备份」/「导出数据备份」。
产物是 `tar.gz`，生成后可在「备份产物」区看到。

### 9.2 上传备份（恢复）

选中实例 → 「上传备份」→ 选一个 `tar.gz`。流程：

1. 原本在运行则**先停进程**（导入期间文件被占用会失败）；
2. 流式接收 → 魔数识别 + 完整性校验；
3. 解压**覆盖**到实例目录；
4. 原本在运行的实例**自动重启**。

**覆盖语义**：只覆盖包内出现的文件，**不删除包外文件**（安全，但意味着旧文件可能残留）。

> 备份来自旧机器时，包内的互联配置可能还指向旧的登录端（如 `127.0.0.1:12345`）。
> 恢复后请用「诊断连接」确认、必要时重跑一遍第 4 步互联配置。

### 9.3 备份产物回收

所有备份产物都落在备份目录，**只增不减**，需要人工清理。总览页对应区域支持：

- 单项删除；
- 按天批量清理（默认 30 天）。

三类产物：

| 产物 | 生成时机 |
|---|---|
| 升级前快照 | 每次点「升级」前自动整目录备份 |
| 定时备份 | 定时任务 kind=backup |
| 手动导出 | 面板导出操作 |

> 定时任务的份数滚动**只认定时备份标记**，不会误删升级前快照。

## 10. 一键升级

选中实例 → 「检查更新」→ 有新版本则出现「升级到 vX.Y.Z」按钮。

点升级会：

1. **自动整目录快照**（生成一份升级前备份，失败则中止升级）；
2. 下载新版本并校验；
3. 替换程序文件；
4. **恢复升级前的运行状态**（原本在跑就自动拉起，原本停着就保持停着）。

### 10.1「管理应用」面板

总览页选中实例后点「管理应用」，面板内容由程序自身能力决定：

- **有自带 WebUI 的程序**（NapCat / LLBot / OlivaDice 等）：面板里是一个「打开 WebUI」按钮，
  点了新开窗口直达该程序自己的面板，登录令牌点一下即可复制。
- **依赖型程序**（NoneBot2）：面板里是「依赖与插件」，可以：

  | 操作 | 说明 |
  |---|---|
  | 安装插件 | 填包名或 pip 规格（如 `nonebot-plugin-alconna`）→ 安装。**首次可能需要几分钟**，取决于网络 |
  | 卸载插件 | 二次确认后删除 `libs/` 下的包文件与 `pyproject.toml` 里的声明；插件自带的数据文件不删 |
  | 同步依赖声明 | 把 `libs/` 里现有的包补写进 `pyproject.toml`。自己手工 `pip install --target libs` 装过插件后用 |

  两条硬性规则：
  1. **实例运行中不能装卸插件**。运行中的进程已经 import 着 `libs/` 里的模块，
     替换文件会得到半新半旧的状态，面板会把按钮置灰并提示先停止。
  2. **装完/卸完需要重启实例**。NoneBot2 不支持配置与插件热加载，
     `pyproject.toml` 的依赖变更也只在下次启动时生效。

  ⚠️ 面板只列 `nonebot-plugin-*` 开头的包作为「插件」——nonebot2 本体、
  fastapi 这类基础依赖不在可卸载列表里（卸掉它们实例就起不来了）。

### 依赖型程序（NoneBot2）的升级略有不同

NoneBot2 没有「下载新程序包」这回事——它装的是一堆 Python 依赖。所以：

- 「检查更新」会提示「该程序为 Python 依赖项目，版本以已装依赖为准」，按钮显示为**「升级依赖」**；
- 点击后执行的是 `pip install -U`，把该实例的全部依赖升到最新版；
- 其余流程不变：照样先整目录备份、照样停机、照样升完自动拉起；
- 首次安装和国内网络较慢时可能需要几分钟（要下载依赖包）。

> 依赖装在实例目录的 `libs/` 里（约 22MB），删除实例时会一并清除。
> **升级依赖后无需手动改配置**——管理器会同步更新 `pyproject.toml` 里的版本号，
> 不会出现「升级完一重启又变回旧版」的情况。

**想自己加插件？** 依赖装在 `libs/` 而非 Python 的全局环境里，所以直接
`pip install xxx` 是装不到这个实例的。请在实例目录里执行
`pip install --target libs xxx`，并把 `xxx` 补进 `pyproject.toml` 的
`dependencies`——两步缺一不可，缺第二步的话 `nb run` 下次同步依赖时会把插件悄悄移除。

## 11. 定时任务

总览页「定时任务」区，支持两类任务：

| 类型 | 说明 |
|---|---|
| **定时重启** | 按「每 X 天 X 小时」的间隔自动重启实例 |
| **定时备份** | 同上，按间隔自动生成备份；可选 full/data 口径，按 keep 份数滚动保留 |

配置项：间隔（天 + 小时，合计 ≥1 小时）、备份口径、保留份数（默认 7）。

每个任务行都有「立即执行」按钮——用于补跑或测试（执行后记 last_run，未满间隔不再重复跑）。
删任务有独立按钮。

## 12. 资源监控

### 12.1 全局内存水位

总览页顶部常驻一条内存水位条（used/total），后台每 **60s** 采样一次内存与 CPU
（**含子进程**——比如 LLBot 主进程只占 3MB，加上子进程才是真实的 157MB）。
占用 ≥90% 时水位条变红告警。阈值可配置。

### 12.2 单实例资源曲线

选中实例 → 「资源曲线」→ 24h 双折线（内存 MB / CPU%），图例给出最新值、峰值、CPU 均值。
采样点落盘持久化，**面板重启不丢历史**。删除实例时同步回收。

可关闭采样：环境变量 `DM_METRICS=0`；调整间隔：`DM_METRICS_INTERVAL`（秒）。

### 12.3 程序包缓存管理

总览页「程序包缓存」区，列出每个程序的本地包：大小、来源（上传/下载缓存）、更新时间、
**是否被实例使用**。

- **部署时优先级**：本地包 > 在线下载。下载成功的包也会缓存下来供后续实例复用。
- **死缓存清理**：「清理未使用」一键删掉没有任何实例在用的包。

## 13. 两版路径对照

| 内容 | 🐧 Linux | 🪟 Windows |
|---|---|---|
| 实例注册表 | `/var/lib/dicemanager/instances.json` | `<项目根>/data/instances.json` |
| 端口分配表 | `/var/lib/dicemanager/ports.json` | `<项目根>/data/ports.json` |
| 管理凭据 | `/var/lib/dicemanager/auth.json` | `<项目根>/data/auth.json` |
| 程序包缓存 | `/var/lib/dicemanager/packages/` | `<项目根>/data/packages/` |
| 备份产物 | `/var/lib/dicemanager/exports/` | `<项目根>/data/exports/` |
| 定时任务 | `/var/lib/dicemanager/schedules.json` | `<项目根>/data/schedules.json` |
| 实例日志 | `/var/log/dicemanager/{id}.log(.1)` | `<项目根>/data/logs/{id}.log(.1)` |
| 资源采样 | `<state>/metrics/<id>.json` | `<项目根>/data/metrics/<id>.json` |
| 程序安装根 | `/opt/<程序名>` | `<项目根>/package/<程序名>` |
| 面板日志 | `journalctl -u dicemanager` | 托盘 / `<项目根>/data/diag.log` |

> 🪟 的「项目根」：开发模式是 `dicemanager_win/`；打包模式是 exe 所在目录。

### 环境变量（两版通用）

| 变量 | 默认 | 作用 |
|---|---|---|
| `DM_STATE_DIR` | 见上表 | 覆盖状态目录 |
| `DM_LOG_DIR` | 见上表 | 覆盖日志目录 |
| `DM_GITHUB_MIRROR` | 空（直连） | GitHub 镜像前缀，如 `https://ghfast.top` |
| `DM_METRICS` | 开启 | 设 `0` 关闭资源采样 |
| `DM_METRICS_INTERVAL` | 60 | 采样间隔（秒） |
| `DM_AUTO_RESUME` | 开启 | 设 `0` 关闭面板重启后自动拉回实例 |
| `DM_RESUME_DELAY` / `DM_RESUME_STAGGER` | 2 / 1.5 | 恢复前的等待与实例间错开秒数 |

## 14. 常见问题排查

### 14.1 部署与登录

| 现象 | 原因与解法 |
|---|---|
| **部署卡住/超时** | 🐧 国内直连 GitHub 慢 → 设 `DM_GITHUB_MIRROR` 镜像；或用「上传压缩包并部署」手动传离线包 |
| **离线包上传失败** | 上限 2GB；🐧 检查 Nginx `client_max_body_size` 是否 ≥2048m |
| **登录二维码不动了** | 日志中心看该实例输出；点向导内「刷新二维码」会重启登录进程 |
| **二维码一直不出现** | 确认该程序真的把二维码打进了输出；Lagrange 类无头部署需预置配置，否则它在等按键 |
| **弹出滑块验证** | 面板只转发链接，**必须你本人在浏览器手动完成**，没有别的办法 |
| **LLBot 提示需要 AUTH TOKEN** | LLBot v8.0.9+ 强制要求，去它的快速登录平台申请后填入向导 |
| **NapCat 提示手动配置** | WebUI API 不可达（token 失效/端口未回读成功）的兜底，按面板指引在 NapCat WebUI 手动创建后回填 |
| **程序启动后立即退出** | 可能是前置依赖缺失（如 🪟 NapCat 需要 Windows QQ 客户端）。向导第 1 步会检查并给下载链接 |
| **部署成功但连不通** | 点「诊断连接」看断在哪一环；多半是 token 不一致或互联配置没写进去（重跑第 4 步） |

### 14.2 运行与状态

| 现象 | 原因与解法 |
|---|---|
| **进程反复重启最终停下** | 触发熔断（300s 内 5 次）。**去看日志找根因**，修好后手动启动。重启计数不复位是正常的 |
| **拓扑图虚线灰（已配置未连接）** | 登录端还没登录，或进程没起来。检查登录端实例的状态 |
| **拓扑图红线（连接失败）** | 点「诊断连接」；多半是 token 不一致或端口被占 |
| **端口被占用** | 分配器从默认端口 +1 探测直到空闲，所以实际端口可能不同于默认值，**以总览显示的为准** |
| **删除实例后端口还被占** | 分配表按 owner 释放；若 30 天内有墓碑记录，同名目录/端口受保护 |
| **面板显示在跑实际全离线** | 旧版本行为。更新后由自动恢复接管；若仍未恢复，手动逐个启动并检查 resume 日志 |
| **关机后实例丢失** | 关机会杀掉子进程，注册表仍记 RUNNING。重启面板会自动拉回（见 §7.3） |
| **🪟 杀进程树不干净** | 极少数情况下程序自身 fork 的孙子进程杀不掉。重启面板后「扫描安装目录」可结束游离进程 |

### 14.3 面板本身

| 现象 | 原因与解法 |
|---|---|
| **WebSocket 连不上**（总览一直转圈） | 🐧 Nginx 缺 `Upgrade`/`Connection` 头，或 token 已被 401 清掉。查浏览器控制台与 `journalctl` |
| **界面正常但功能全 500** | 检查数据目录与日志目录权限 |
| **忘记管理密码** | 见 §4.3，删凭据文件重启 |
| **界面显示乱码/错位** | 🪟 仓库里 Windows 子目录的 README 用 LF，本地开发副本用 CRLF，属正常现象 |
| **🪟 双击 exe 一闪而过** | 面板不该崩溃。看 `<项目根>/data/diag.log`，里面记录了启动各阶段的诊断信息 |

## 15. 安全须知

- **面板只监听 `127.0.0.1`**，外部机器无法直接访问。🐧 要对外访问必须自己配 Nginx + TLS，
  且**务必带 WebSocket 的 `Upgrade`/`Connection` 头**。
- **密码安全**：PBKDF2 哈希存储，登录失败限速，token 恒定时间比较。
  凭据文件 🐧 是 `0o600` 权限（`umask 0o077`），🪟 靠项目目录天然隔离。
- **命令注入防护**：启动命令一律由后端 `build_start_cmd` 构建，前端从不传命令。
- **包完整性**：manifest 可选 `sha256` 字段校验安装包；所有包按魔数识别真实格式。
- **升级与恢复都会先自动备份**，出错可回退。
- **别把面板暴露到公网**。🐧 如必须暴露，请加 HTTPS + 访问控制（IP 白名单 / Basic Auth 二次门）。
- **官方机器人通道**（海豹）：免登录端、免互联，规避协议端封号风控，
  但官方接口的主动消息和群管能力受限。根据自己的使用场景选。
