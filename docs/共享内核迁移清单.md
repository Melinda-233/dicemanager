## 2. 差异归因总表（23 个有差异文件）

### A. 路径默认值 — 5 个，合并进 `core/pathutil.py`

| 文件 | Windows 侧改动 | 处置 |
|---|---|---|
| `api/context.py` | `default_state_dir()` / `default_log_dir()` | 改用 pathutil，pathutil 内平台分支 |
| `core/exports.py` | `default_state_dir()` | 同上 |
| `core/packages.py` | `default_state_dir()` | 同上 |
| `core/locks.py` | `default_lock_dir()` | 同上 |
| `api/app.py` | `default_state_dir()` | 同上 |

pathutil 上提后必须**保持 Linux 行为字节级不变**：

```python
def default_state_dir() -> Path:
    if os.name == "nt":
        return project_root() / "data"        # 单机本地：exe 同级
    return Path("/var/lib/dicemanager")       # 服务器：FHS 位置，不可改

def default_lock_dir() -> Path:
    if os.name == "nt":
        return default_state_dir() / "locks"
    return Path("/tmp/dicemanager")           # Linux 沿用原值
```

### B. 平台原语 — 4 个，抽 `core/platform/`

| 文件 | POSIX 实现 | Windows 实现 | 差异行 |
|---|---|---|---|
| `core/process.py` | `start_new_session` + `killpg` | `CREATE_NEW_PROCESS_GROUP` + `taskkill /T` | 52 |
| `core/scanner.py` | 字符串 `/` 前缀匹配 | `Path.is_relative_to()` | 42 |
| `core/locks.py` | `fcntl.flock` | `msvcrt.locking` | 11 |
| `core/adopt.py` | `/proc` 回退查连接 | 直接返回 `None` | 3 |

**注意 `scanner.py` 与 `adopt.py` 要取 Windows 侧实现**——Windows 版是对旧实现的**改进**（`is_relative_to` 修复了无尾斜杠失配；`os.name != "posix"` 提前返回避免了无谓 psutil 调用），不是平台特化。合并后 Linux 行为更正确，需补跑 `tests/test_scanner.py`、`tests/test_adopt.py`。

### C. 边缘分化 — 6 处，进 `editions/`

| # | 分化点 | server（Linux） | desktop（Windows） |
|---|---|---|---|
| C1 | **鉴权模型** | 多用户 + 配额（auth.json v2，admin/user 角色、会话表、登录端 QQ 数与实例数配额） | 单用户 + 首启 WebUI 设密码 |
| C2 | **首启端点** | 无 | `/needs-setup`、`/setup`（仅未初始化可用，已初始化返 409） |
| C3 | **服务化** | `/panel/restart`（systemd `Restart=always` 拉起；裸跑用接班进程 exec） | 无（托盘常驻，重启无意义） |
| C4 | **网络暴露** | `core/firewall.py` 的 `open_port()` 放通端口 | no-op（`adapters/base.py` 内 `def open_port(port): return None`） |
| C5 | **路径策略** | `/var/lib`、`/var/log`、`/opt/...` 固定部署位 | 项目根 `data/`、`package/`，随 exe 走 |
| C6 | **分发打包** | systemd unit + nginx + tar.gz | PyInstaller 单文件 exe + 托盘 |

C3 对应前端 `Overview.vue` 的「重启面板」按钮与遮罩层（约 60 行模板 + 25 行逻辑 + 12 行 CSS），按 build flag 条件渲染。

### D. 文案与 bug 修复 — 3 个，直接统一（**不是分化**）

| 文件 | 差异 | 处置 |
|---|---|---|
| `web/src/pages/Password.vue` | 18 行，仅「密码」↔「管理密码」措辞 | 统一取「管理密码」 |
| `web/src/App.vue` | 34 行，Windows 侧是**未登录路由守卫修复**：未登录时 `#/logs`、`#/wizard` 会停住，看不到设密码界面 | 取 Windows 侧实现（这是 bug 修复，两版都该有），再叠回 server 的 restart 分支 |
| `web/src/api.js` | 13 行，`needsSetup`/`setup` 与 `restartPanel` 各自独有 | 全部保留，按 build flag tree-shake |

**这 3 个不要当成平台差异处理**，否则会把 bug 修复永久锁在单侧。

### E. 待定 — 1 个

`adapters/__init__.py`：Windows 侧加载清单时把 `install_root` 覆盖为 `default_install_root()`，注释称修复了 `%LOCALAPPDATA%` 占位符从未展开的 latent bug。**需确认 Linux 版是否同样存在此 bug**——若是，应修复共享代码而非保留为分化。

### P2 — 路径层统一

**验收**：Linux 上 `STATE_DIR` 仍为 `/var/lib/dicemanager`、`LOCK_DIR` 仍为 `/tmp/dicemanager`（**必须逐项断言，不能靠看代码**）；Windows 上 data 落在项目根/exe 同级。

### P3 — 平台原语抽层

1. 新建 `core/platform/{__init__,posix,win32}.py`。

## 4. 与「拆两个仓库」的关系

本清单产出的是**单仓库**结构，但它同时让将来的拆分变便宜——因为边界已经显式化：

- 打包时 `editions/server/` 不进 exe，`editions/desktop/` 不进 tar.gz；
- 若日后确需 `DiceManager-Linux` / `DiceManager-Windows` 两个仓库，
  用 `git filter-repo --subdirectory-filter` 或按 `editions/` 切分即可，
  不必再手工判断哪些文件该归谁。

**先做本清单，再决定拆不拆**——顺序反过来会拆出两份各含 96% 重复代码的仓库。
